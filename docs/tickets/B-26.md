# B-26 — Tirage au sort par le serveur (poules et phases finales)

- **Statut** : Ouvert (2026-11-16).
- **Décision utilisateur (2026-11-16)** : amende A1 (2026-10-20). L'appli peut **tirer au sort** elle-même ; la saisie d'un tirage physique (affiche par affiche, poule par poule) **reste possible**. Valable pour le tirage des poules et pour chaque tour de phase finale.
- **Règles à respecter** :
  - poules : RG11, têtes de série d'abord (une par poule), puis les autres participants poule après poule ; tailles de poule de la configuration retenue ;
  - phases finales : RG13 et RG14, tirage global du tour sur le vivier du tour (qualifiés directs et issus des barrages mélangés) ;
  - hasard cryptographique (`crypto.randomInt`, pas `Math.random`), mélange de Fisher-Yates.
- **Contrat proposé** (à confirmer par le backend-lead, Spec API à mettre à jour) : le serveur produit les affectations et les **écrit dans le brouillon existant** (même format que `PUT /tirages/{id}/affectations`), sans valider. L'organisateur relit puis valide avec la route de validation actuelle. Brouillon déjà commencé : 409, sauf demande explicite de remplacement (même logique que « Remplacer le brouillon »).
- **Critères** : tests unitaires du mélange (contraintes RG11 / RG14 tenues sur N tirages, distribution non biaisée vérifiée simplement) ; tests API ; typecheck, `test:run`, `test:release` verts ; Spec API et Spec fonctionnelle (section Tirage au sort) mises à jour dans Obsidian.
