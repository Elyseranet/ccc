# B-29 — Inviter un joueur sans compte : saisir son email et envoyer l'invitation

- **Statut** : Fermé (2026-11-17) @ `a66d9529` (branche `f6db760f`). Gates sur develop après merge : typecheck vert, `test:run` 1539 / 0, `test:release` vert ; branche : `test:bundle` vert, test:api invitations 18/18 (5 nouveaux) + competitors, rate-limit, admin-editions, send-failure, public-read 83/83. Dev déployé `a66d9529` : `PUT /competiteurs/x/compte` sans session = 401 ; détail public d'un compétiteur sans `account` ni email. Contrat final : 409 `EMAIL_ALREADY_USED` (code existant, pas `EMAIL_TAKEN`), 409 `ACCOUNT_ACTIVE` (nouveau) ; `account` porté par `GET /competiteurs/{id}` pour un admin seulement. Non vérifié : envoi SMTP réel (tests sur l'adaptateur de capture). Connu, non bloquant : pas de rate limit (comme A14) ; corriger avec le même email réémet une invitation ; invitation expirée = `INVITED` + date passée sur la fiche.
- **Demande utilisateur (2026-11-17)** : l'admin doit pouvoir donner un email à un participant et lui envoyer un mail pour qu'il récupère son compte (ses stats, etc.).
- **Constat** : `POST /competiteurs/{id}/invitation` (A14) ne fait que renvoyer une invitation à un compte déjà créé (`INVITED`) ; sans compte (archives, joueur créé sans email) → refus. Aucune route ne pose un email sur un compétiteur existant.
- **Décisions utilisateur (2026-11-17)** :
  - sans compte : l'admin saisit l'email → création du compte `INVITED` lié au compétiteur + envoi de l'invitation ;
  - compte `INVITED` : l'admin peut **corriger l'email** et renvoyer (ancien lien invalidé) ;
  - compte actif : l'email **n'est pas modifiable** par l'admin (409), c'est le joueur qui le gère.
- **Contrat proposé** (à confirmer, Spec API) : `PUT /api/v1/competiteurs/{id}/compte` `{ email }` (administrateur) → 200 `{ accountStatus, invitationSent, invitationExpiresAt }`. 409 email déjà pris par un autre compte, 409 compte actif, 404, 400. Réutilise `issueInvitation` / `sendInvitationEmail` (échec d'envoi : `invitationSent: false`, rien n'est annulé, comme A14). Le détail admin du compétiteur expose `accountStatus` (`NONE` / `INVITED` / `ACTIVE`) et l'email (admin seulement, jamais public).
- **Critères** : tests API (archive sans compte → compte + mail dans Mailpit de test, correction d'un INVITED avec ancien lien 410, actif refusé, email pris refusé, 403 participant) ; typecheck, `test:run`, `test:release`, test:api concernés verts ; Spec API à jour.
