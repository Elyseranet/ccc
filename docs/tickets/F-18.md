# F-18 — Admin : corriger un score déjà validé

- **Statut** : À faire. Ouvert le 2026-11-04 par le chef de projet (décision utilisateur, `decisions.md` 4743e48 : la correction est sortie de F-08).
- **Pilote** : `frontend-lead`, avec l'`ui` pour le dessin.
- **Dépend de** : F-08 mergé (écran des scores) ; T-SEC-08 mergé (contrôle de version `If-Match`, 428/412).

## Contexte
- La route existe : `POST /api/v1/matchs/{id}/correction` (A15). L'opération est journalisée ; elle répond 409 si un tour suivant est engagé (R-3) ; elle exige `If-Match` (428 sans en-tête, 412 si la version est périmée).
- La maquette `admin-matchs.html` ne dessine ni action ni formulaire de correction, et l'endpoint n'est pas encore dans `API_ROUTES`.

## Périmètre
1. **ui** : dessiner, dans `admin-matchs.html`, l'action « Corriger » sur un match validé, le formulaire de correction et l'état « tour suivant engagé » (refus 409), puis mesurer contre le rendu Origam.
2. **Intégration** dans l'écran des scores, en réutilisant le formulaire de saisie et la couche HTTP de F-08 (en-tête de version générique). Ajouter l'endpoint à `API_ROUTES`.
3. Erreurs traduites : 409 (tour suivant engagé), 412 (version périmée : recharger), 428.
