# B-15 — Admin : flux d'activité du tableau de bord

- **Statut** : Bloqué (arbitrage A17)
- **Vague** : 4
- **Worktree** : `../CCC-B-15`, branche `feature/B-15-admin-activity`
- **Dépendances** : B-11 (tirages, auteur) et B-12 (validations, auteur).
- **Origine** : écart C7 de FA-03. La maquette du tableau de bord admin montre une « activité récente avec auteur », alors qu'aucune spec ne la demande.

## Endpoint

| Méthode et chemin | Accès | Réponse |
|---|---|---|
| `GET /api/v1/admin/editions/{id}/activite?limit=` | administrateur | `IAdminActivityItem[] { kind, at, actor: { id, displayName }, target: { type, id, label } }`, triée par `at` décroissant |

## Conception

Elle suit l'option recommandée en A17 : un flux dérivé, sans nouvelle table. Une `UNION` est faite sur `matches.validated_at` / `validated_by_user_id`, `draws.created_at` / `created_by_user_id` et `draws.validated_at` / `validated_by_user_id`. Les types d'activité vivent dans `shared/enums/admin-activity.enum.ts`.

Si A17 retient l'option (b), une table `audit_events` est ajoutée (migration avec `down`), alimentée dans la transaction de chaque écriture admin. Le périmètre est alors à réécrire.

## Critères d'acceptation

- [ ] Tests d'API : participant renvoie 403, anonyme renvoie 401.
- [ ] Tests d'API : une validation de match puis une validation de tirage apparaissent, dans l'ordre antéchronologique, avec leur auteur.
- [ ] `limit` est borné : 400 hors bornes.
- [ ] L'acteur n'expose que son nom affiché : ni email, ni téléphone.
