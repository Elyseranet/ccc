## Endpoint

| Méthode et chemin | Accès | Réponse |
|---|---|---|
| `GET /api/v1/admin/editions/{id}/activite?limit=` | administrateur | `IAdminActivityItem[] { kind, at, actor: IAdminActor \| null, target: TAdminActivityTarget }`, triée par `at` décroissant, `limit` défaut 20, maximum 100. `TAdminActivityTarget` est une union discriminée sur `type` (contrat publié par B-17, relu par le front le 2026-10-21) : cible MATCH `{ id, matchSequence, roundKind, poolNumber, sides: [IMatchSide, IMatchSide] }` avec le score validé ou corrigé, et cible DRAW `{ id, drawKind, roundKind, poolCount, seedCount }`. Pas de `label` (i18n) |

## Conception

Elle suit l'option recommandée en A17 : un flux dérivé, sans nouvelle table. Une `UNION` est faite sur `matches.validated_at` / `validated_by_user_id`, `draws.created_at` / `created_by_user_id` et `draws.validated_at` / `validated_by_user_id`. Les types d'activité vivent dans `src/enums/admin-activity.enum.ts` (ARCH-4 : pas de `shared/`).

Si A17 retient l'option (b), une table `audit_events` est ajoutée (migration avec `down`), alimentée dans la transaction de chaque écriture admin. Le périmètre est alors à réécrire.

## Critères d'acceptation

- [ ] Tests d'API : participant renvoie 403, anonyme renvoie 401.
- [ ] Tests d'API : une validation de match puis une validation de tirage apparaissent, dans l'ordre antéchronologique, avec leur auteur.
- [ ] `limit` est borné : 400 hors bornes.
- [ ] L'acteur n'expose que son nom affiché, via `toAdminActor`, le mapper partagé avec B-11 et B-12. Il n'expose jamais l'email ni le téléphone d'un compétiteur. Pour un admin sans compétiteur, son email sert de nom affiché, visible des seuls admins (décision utilisateur 2026-11-04, `decisions.md` 4743e48).
- [ ] Le flux n'émet que `MATCH_VALIDATED`, `DRAW_CREATED` et `DRAW_VALIDATED`. `MATCH_CORRECTED` est retiré de `ADMIN_ACTIVITY_KIND`, puisque rien ne le consomme. Une correction écrase `validated_at` et `validated_by_user_id` : un match corrigé apparaît donc en `MATCH_VALIDATED`, daté de la correction et attribué à son auteur (décision utilisateur 2026-11-04).
