# F-38 — Boutons primaires désactivables : appliquer `usePrimaryActionButton` (suite de F-37)

- **Statut** : Ouvert (2026-11-13). Défaut trouvé par frontend-lead pendant la revue de F-25. Même cause que F-37.
- **Constat** : un `origam-btn` désactivé ignore les tokens de l'état désactivé quand `bg-color` et `elevation` lui sont passés en ligne (fiche `docs/tickets/origam/btn-etat-desactive-tokens-bgdisabled-non-lus.md`, section « bg-color et elevation en ligne »). Désactivé, le bouton garde alors sa couleur et son ombre. F-37 corrige les boutons « Arrêter la liste » (F-24) et « Valider » (F-25) avec le composable `usePrimaryActionButton`, livré par F-25. frontend-lead compte environ 15 autres boutons admin désactivables dans le même cas (exemples : `DrawRecap`, `ScoreEntryForm`).
- **Périmètre à établir** : sur develop @ `76d20755`, 24 fichiers de `src/components` et `src/pages` passent `bg-color="primary"`, dont des écrans publics et compte (`HomeHero`, `LoginForm`, `ProfileForm`…). Seuls les boutons qui peuvent être désactivés sont concernés. Le dev dresse la liste exacte avant de coder (`grep -rn 'bg-color="primary"' src`, puis lecture du `:disabled`).
- **Attendu** : chaque bouton concerné passe par `usePrimaryActionButton`, sans nouveau code de style. La hauteur suit la maquette de chaque écran : ne pas passer à `x-large` sans le vérifier dans la maquette.
- **Critères** :
  - les zones visuelles existantes des écrans touchés restent sous 1 % ;
  - les tests de composant de l'état désactivé passent ;
  - typecheck, `test:run` et Playwright verts.
