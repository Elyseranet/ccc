# F-03c — Podium de l'édition : étoiles du finaliste et des demi-finalistes (B-19)

- **Statut** : À faire. Ouvert le 2026-10-28 par `frontend-lead`, après le merge de B-19 (566525c). Démarre après le merge de F-03b.
- **Origine** : F-03a/F-03b masquent les étoiles du finaliste et des demi-finalistes dans le podium (documenté dans le spec visuel), faute de titres à date dans le contrat. B-19 les expose.
- **Décision UI** (2026-10-28) : étoiles pour tout joueur qui a des titres, quelle que soit sa place au podium ; **le bloc du champion n'en a pas** (traitement de titre, pas un PlayerLink).
- **Dépend de** : F-03b (mergé), B-19 (mergé).

## Périmètre

1. Finaliste : étoiles depuis `IEditionFinal.runnerUpTitlesToDate` (lu seulement si `final` n'est pas null).
2. Demi-finalistes : lignes « Demi-finale » depuis `IEditionSummary.semiFinalists` (`IEditionPodiumEntry { competitor, titlesToDate }`), **dans l'ordre du serveur, jamais retrié** ; aucune ligne si la liste est vide.
3. Rendu des étoiles : celui de PlayerLink (étoiles si `titles > 0`), comme partout ailleurs.
4. Retirer le masquage des étoiles dans le spec visuel du podium ; aucune donnée inventée.

## Critères d'acceptation

- [ ] e2e sur données réelles : une édition dont le finaliste a au moins un titre à date montre ses étoiles ; une édition dont un demi-finaliste a des titres les montre ; une édition sans demi-finale jouée n'affiche aucune ligne de demi-finaliste (sur l'état de la base de test : 2026 en phase de poules, T-QA-03, si mergé).
- [ ] Zones du podium ≤ 1 % sans masque des étoiles ; image d'écart relue.
- [ ] typecheck à 0, test:run, Playwright complet verts ; gitleaks propre.

## Réalisation (dev-f06, 2026-10-28)

- `buildEditionPodium` lit `final.runnerUpTitlesToDate` (0 sans finale) et `semiFinalists` (ordre du serveur, jamais retrié, aucune ligne si `[]`). Le bloc du champion reste un texte de titre, sans étoiles. `EditionSummary` passe `titles` à `PlayerLink`.
- **Étoiles sous le nom, comme la maquette.** Dans la maquette (`.ed-podium__rest li`, grille), les étoiles sont une rangée sous le nom ; dans `PlayerLink` elles étaient en ligne. Mesuré : avec les étoiles en ligne, zone podium 6,3 % (1440 px) et 10,3 % (390 px) ; en colonne sans écart 1,1 % / 1,8 % (hauteur 292 px contre 294 px) ; avec l'écart de `space-1` entre les rangées, **0,086 % / 0,097 %**. `PlayerLink` expose pour cela trois variables (`--player-link---content-direction`, `---content-align`, `---content-gap`) et `---stars-margin`, posées par `EditionSummary` ; valeurs par défaut inchangées ailleurs.
- Spec visuel : le masque des étoiles est retiré pour la zone podium ; la maquette porte des étoiles d'exemple, on y met celles de l'app rang par rang et on retire les rangées en trop (sinon la comparaison testerait la donnée de la maquette). Le masque reste sur les autres zones (étoiles des tirages et des participants : hors périmètre).
- e2e sur données réelles : `tests/e2e/a11y/F-03c.spec.ts`, éditions 2025, 2024, 2021, 2016 et 2012a comparées à l'API (ordre, nombre d'étoiles, 0 étoile sans titre, aucune étoile dans le bloc du champion).
