## Réalisation (2026-11-14, dev-f08)

- Les 8 copies étaient identiques (3 variables sur la classe du bouton) et tous les boutons portaient `size="small"` : la maquette (`hh.css`) donne `.btn--sm` (44 px, padding 16 px, police sm) pour tous. Recette retenue, par props (PROPS-FIRST) : sans `size` (le thème pose `large`, 44 px), `font-size="sm"` et `padding-inline="4"` ; `variant`, `color` et `font-weight` inchangés. Les 8 blocs CSS locaux et les classes devenues sans règle sont supprimés ; grep : plus aucun `--origam-btn---height` local de cette recette. Même recette que `QualificationTies` (F-38) et le bouton « Vérifier l'état » (F-26).
- `padding-inline` d'Origam est posé en **style en ligne** : la feuille de style ne peut pas l'annuler. `PlayerOpponents.vue`, qui annulait le padding du lien sous 760 px, le fait donc par la même prop : `:padding-inline="linkPadding"` (`useBelowWidth`, déjà utilisé par `ScoreEntryDialog`, seuil `PLAYER_OPPONENTS_COMPACT_BREAKPOINT_PX` dans `players.const`). Aucun `:deep`, aucun `!important`. Limite connue : faux au rendu serveur, comme `useBelowWidth` (l'écran démarre en bureau puis bascule).
- `PlayerOpponents` `__see-all` (`--origam-btn---padding-lg: space-3`) : autre bouton, hors recette, laissé.
- `min-width` : `large` 78 px contre 50 px pour `small` ; mesuré dans les zones (boîtes maquette / application identiques) : voir la mesure.
