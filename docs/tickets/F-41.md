## Réalisation (2026-11-14, dev-f08)

- Les 8 copies étaient identiques (3 variables sur la classe du bouton) et tous les boutons portaient `size="small"` : la maquette (`hh.css`) donne `.btn--sm` (44 px, padding 16 px, police sm) pour tous. Recette retenue, par props (PROPS-FIRST) : sans `size` (le thème pose `large`, 44 px), `font-size="sm"` et `padding-inline="4"` ; `variant`, `color` et `font-weight` inchangés. Les 8 blocs CSS locaux et les classes devenues sans règle sont supprimés ; grep : plus aucun `--origam-btn---height` local de cette recette. Même recette que `QualificationTies` (F-38) et le bouton « Vérifier l'état » (F-26).
- `padding-inline` d'Origam est posé en **style en ligne** : la feuille de style ne peut pas l'annuler. Le lien « Face-à-face » de `PlayerOpponents.vue`, dont le padding est annulé sous 760 px, n'utilise donc PAS la prop : `font-size="sm"` reste une prop, le padding et la largeur minimale passent par les variables d'Origam dans une règle de mise en page locale avec media query (`--origam-btn---padding-lg` : 16 px en bureau, 0 sous 760 px ; `--origam-btn---min-width: 0` sous 760 px, sur `.player-opponents__link.origam-btn` car `large` pose cette variable sur le bouton lui-même). Pas de JS : un essai avec `useBelowWidth` (faux au rendu serveur) faisait sauter la ligne après l'hydratation, écarté.
- `PlayerOpponents` `__see-all` (`--origam-btn---padding-lg: space-3`) : autre bouton, hors recette, laissé.
- `min-width` : `large` 78 px contre 50 px pour `small`. Mesuré (2026-11-14, 144 zones comparées à develop + F-20, 1440 et 390) : seul le lien « Face-à-face » mobile de `PlayerOpponents` bougeait (texte recentré, +6 px : 0,080 % → 0,368 % sur `joueur-adversaires` @390) ; la prop `min-width` à 0 sous 760 px a rétabli 0,080 %.
