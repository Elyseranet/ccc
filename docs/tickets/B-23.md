# B-23 — Codes d'erreur distincts sur la saisie, la validation et la correction d'un score (demandé par F-18)

- **Statut** : **En revue** (livraison au `backend-lead`).
- **Origine** : F-18 (front de la correction de score). Trois causes différentes renvoyaient le même `409 CONFLICT`, qu'on ne distinguait que par le message anglais.
- **Worktree** : `../CCC-B-23`, branche `feature/B-23-correction-error-codes`.

## Constat (vérifié dans `src/services/match.service.ts`)

`correctMatch` et `assertWritable` (saisie et validation) levaient `conflict('...')` pour : match non `VALIDATED`, résultat importé des archives, édition `CLOSED`.

## Contrat

| Cause | Code (409) | Où |
|---|---|---|
| match non `VALIDATED` | `MATCH_NOT_VALIDATED` (nouveau) | correction |
| `RESULT_UNKNOWN` ou vainqueur importé | `ARCHIVE_RESULT_READ_ONLY` (nouveau) | saisie, validation, correction |
| édition `CLOSED` | `EDITION_CLOSED` (existant, `editionClosed()`) | saisie, validation, correction |

Inchangés : `NEXT_ROUND_ENGAGED`, `VERSION_CONFLICT`, `MATCH_ALREADY_VALIDATED`, `SCORE_MISMATCH`, 428. Restent en `CONFLICT` : tour non ouvert, validation sans score saisi.
