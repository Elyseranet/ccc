### Listes : `ul` / `ol` natifs conservés, pourquoi

Mesure (rendu réel de `<origam-list tag="ol">` avec deux `<origam-list-item tag="li">`, test de composant jetable, non commité) :
`<ol class="origam-list …" tabindex="0" role="list">`, chaque item rend `li.origam-list-item[role=listitem]` avec un `span` de fond, un `div.__content` et un `div.__title`. Le DS pose donc **un arrêt de tabulation (`tabindex="0"`) sur toute liste**, même non sélectionnable, plus des gestionnaires focus / clavier / souris, et un balisage interne imposé par item.

- Une liste de contenu de document n'est pas interactive : un arrêt de tabulation sur chacune est un défaut d'accessibilité (focus sans action), et dans `PlayerJourney` la liste est `aria-hidden="true"` (focusable dans une zone masquée aux technologies d'assistance).
- Le balisage interne par item (fond, contenu, titre) ne peut pas porter les cartes, grilles et lignes de classement actuelles sans les réécrire : l'écart visuel dépasserait le seuil de 1 %.

| Fichier | Liste | Raison de garder le natif |
|---|---|---|
| `GoldenRules` | 2 `ol` (cartes, liste) | liste de contenu ordonnée, items = cartes de la maquette |
| `PalmaresTitles` | `ol` | liste ordonnée de cartes (une carte `origam-card` par édition) |
| `PalmaresMostTitled` | `ul` | liste de contenu (ex æquo), items mis en forme par la maquette |
| `RulesTournament`, `RulesVariants` | `ul` (grille) | grille de cartes `origam-card`, contenu de document |
| `RulesGame` | `ol` | étapes ordonnées (l'ordre est le sens), items = cartes |
| `HomeBento` | `ol` (classement) | lignes de classement en grille, non interactives (le lien est dans `player-link`) |
| `HomeCurrentEdition` | `ol` | résultats, lignes de maquette |
| `PlayerJourney` | `ol` | graphique décoratif `aria-hidden` : un arrêt de tabulation y serait un défaut |
| `PlayerStats` | `ul` (grille) | grille de cartes `origam-card` |
| `MatchQueue` | `ol` | file ordonnée de cartes, déjà justifiée dans le composant (« contenu de document, pas un listbox applicatif ») |

Si l'utilisateur veut malgré tout `origam-list` pour ces listes, il faut d'abord une option du DS qui retire le `tabindex` sur une liste non sélectionnable (à ouvrir côté Origam) : sans elle le remplacement dégrade l'accessibilité.
