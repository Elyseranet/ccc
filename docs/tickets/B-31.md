## Arbitrages à poser à l'utilisateur

**Q1 — Que devient un administrateur ACTIF retiré ?**
- (a) **Recommandé** : rétrogradé `PARTICIPANT`, sessions révoquées. Garde sa fiche et ses stats s'il joue (cohérent avec B-32), garde l'auteur de ses validations dans le flux d'activité. Aucune migration. Un ex-admin sans fiche garde un compte qui ne voit que la partie publique.
- (b) Nouveau statut `DISABLED` : connexion refusée. Migration de l'enum `user_status` + `resolveSession` et login à adapter ; un admin-joueur perd l'accès à son compte joueur.
- (c) Suppression du compte : ses validations perdent leur auteur (`ON DELETE SET NULL` sur `matches` et `draws`), un admin-joueur perd son compte.

**Q2 — Retirer une invitation d'administrateur jamais activée (compte INVITED sans fiche)**
- (a) **Recommandé** : supprimer le compte ; ses invitations partent en cascade, le lien répond 404. Il n'a rien pu faire, rien n'est perdu.
- (b) Même traitement que Q1 (rétrogradé `PARTICIPANT` INVITED) : laisse un compte orphelin activable par un lien encore valide.

**Q3 — Un administrateur peut-il retirer son propre accès ?**
- (a) **Recommandé** : non (409 `CANNOT_REVOKE_SELF`), un autre admin doit le faire. Évite qu'un clic malheureux verrouille la personne hors de l'admin.
- (b) Oui, s'il n'est pas le dernier admin actif.

**Q4 — Inviter comme admin l'email d'un compte joueur existant**
- (a) **Recommandé** : promotion du même compte (`role` → ADMIN, fiche conservée). C'est la voie naturelle pour qu'un joueur devenu admin garde un seul compte et ses stats (objectif de B-32).
- (b) Refus 409 `EMAIL_ALREADY_USED` : il faudrait alors une autre adresse, donc deux comptes pour la même personne.

**Q5 — Promotion d'un joueur déjà ACTIF : prévenir par mail ?**
- (a) **Recommandé** : oui, mail d'information sans lien de connexion (« vous êtes désormais administrateur »). Permet à la personne de signaler une élévation de droits non voulue.
- (b) Non : promotion silencieuse.

**Q9 — Journalisation des actions sur les administrateurs**
- (a) **Recommandé** : logs structurés seulement (`LOG_EVENT`, sans email ni jeton), conforme à A17 (pas de table d'audit).
- (b) Table d'audit + entrées dans le flux d'activité du tableau de bord : migration, revient sur A17.

**Q10 — Texte du mail administrateur** (même gabarit F-66)
- (a) **Recommandé** : sujet « Votre accès administrateur à la Cotentin Caps Cup », phrase « L'organisateur de la Cotentin Caps Cup vous a donné un accès administrateur : un compte vient de vous être créé sur le site du CCC. » — à valider mot pour mot.
- (b) Faire rédiger le texte par le rédacteur / ui-f66 avant implémentation.
