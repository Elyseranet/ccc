# B-08 — Authentification, sessions, rôles et profil (`/auth/login`, `/auth/logout`, `/moi`)

- **Statut** : À faire. A2 et A4 tranchés (2026-10-20).
- **Vague** : 2
- **Worktree** : `../CCC-B-08`, branche `feature/B-08-auth`
- **Dépendances** : B-01 et B-02. **Bloque** B-09, B-10, B-11, B-12, B-13 et B-14.

## Périmètre

A2 : **session serveur en base et cookie `httpOnly`**.

1. **Migration M2 `CreateIdentitySchema`**
   - `users` : `id`, `email` (unique, normalisé en minuscules), `password_hash?`, `role` (`USER_ROLE` : `ADMIN` \| `PARTICIPANT`), `status` (`USER_STATUS` : `INVITED` \| `ACTIVE`), `competitor_id?` (unique, FK), `created_at`, `last_login_at?`.
   - `sessions` : `id`, `user_id`, `token_hash`, `expires_at`, `created_at`, `last_seen_at`, `revoked_at?`.
   - FK des colonnes `*_by_user_id` de M1.
   - `down` documenté.
2. **Mots de passe**
   - `node:crypto` `scrypt`, avec sel aléatoire et comparaison en temps constant, **sans nouvelle dépendance**.
   - Les paramètres vivent en constante. La politique de longueur minimale n'est **pas spécifiée** (ST, « Sécurité ») : la valeur proposée est à valider en revue.
3. **Routes**
   - `POST /api/v1/auth/login` :
     - réponse 200 et cookie `HttpOnly; Secure; SameSite=Lax; Path=/` ;
     - 401 avec un message identique, que l'email soit inconnu ou le mot de passe faux ;
     - limite de débit par IP **et** par email.
   - `POST /api/v1/auth/logout` : révoque la session ; idempotent.
   - `GET /api/v1/moi` : `IMe { id, email, role, competitor: ICompetitorPublic & { phone } }`. C'est la **seule** route qui renvoie les données de contact, et uniquement au titulaire.
   - `PATCH /api/v1/moi` : liste blanche **téléphone** (A4). L'avatar ne passe plus par `PATCH /moi` mais par le téléversement de B-16 (AV-1, 2026-10-20) ; le champ `avatarUrl` sort de la liste blanche, et B-16 en fait la migration. Le pseudo est réservé à l'administrateur. Le **mot de passe** se change par `PATCH /moi` avec `currentPassword` + `newPassword` (vérification de l'ancien, proposition à valider en revue), et révoque les autres sessions.
4. **Middleware**
   - `server/middleware/auth.ts` résout la session et pose `event.context.user`.
   - `server/utils/auth/require-role.util.ts` répond 401 sans identité, 403 avec un rôle insuffisant.
   - Les routes publiques ne passent pas par le garde-fou.
5. **Bootstrap du premier administrateur**
   - Une commande CLI `npm run user:create-admin` lit l'email sur l'entrée, puis génère un lien d'invitation, ce qui réutilise B-09.
   - Aucun mot de passe par défaut, ni en dur ni en variable d'environnement.
6. **CSRF**
   - Cookie `SameSite=Lax`, et vérification d'`Origin` sur toute méthode non-GET.
   - Les écritures admin sont toutes en `POST`, `PUT`, `PATCH` ou `DELETE`.

## Paramètres vérifiés (revue du 2026-10-20)

- scrypt N=2^16, r=8, p=2 : l'un des profils listés par https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html (consultée le 2026-10-20 ; le profil de base est N=2^17, r=8, p=1).
- Mot de passe de 15 à 128 caractères, et ancien mot de passe exigé pour le changer : https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html (« shorter than 15 characters are considered to be weak » sans MFA ; maximum d'au moins 64 ; « Current password verification »).
- Cookie `__Host-` en production : https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html (« Recommended for session IDs »).
- Écritures sans en-tête `Origin` acceptées (pas un navigateur) ; la défense CSRF repose sur `SameSite=Lax` et sur la vérification d'`Origin` quand il est présent. Documenté dans le README.
- IP derrière un proxy : relève de T-SEC-02.
- **SEC-A1** (décision utilisateur 2026-10-20) : une session expire après **2 h d'inactivité**, avec une **durée maximale de 12 h**. Tests : expiration à l'inactivité, expiration absolue.
- **SEC-A2** (décision utilisateur 2026-10-20) : pas de blocage dur. Ralentissement progressif **par compte** : délai exponentiel plafonné après 5 échecs, avec la limite par IP conservée, et une commande CLI `user:unlock`. Tests : délai croissant, compte d'un tiers accessible après le délai, commande de déblocage.
