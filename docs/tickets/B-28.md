# B-28 — Supprimer une édition créée dans l'appli

- **Statut** : Ouvert (2026-11-16).
- **Demande utilisateur (2026-11-16)** : pouvoir supprimer une édition « si on a merdé » pour tout ressaisir à la main.
- **Décisions utilisateur (2026-11-16)** :
  - supprimables : **toutes les éditions d'origine `APP`**, clôturées comprises (leurs points disparaissent alors des classements ACP et All Time) ; les archives (`LEGACY_IMPORT`) restent protégées ;
  - les **profils compétiteurs** créés pour l'édition sont **conservés** : seules les participations de l'édition sont effacées (pas de doublon ni de nouvelle invitation à la ressaisie).
- **Contrat proposé** (à confirmer, Spec API à mettre à jour) : `DELETE /api/v1/editions/{id}` (administrateur). 204 ; 409 code dédié pour une archive ; 404 inconnue. Une transaction : participations, poules, tours, tirages et affectations, matchs et côtés, départages, qualification, points / classements dérivés, puis l'édition. Aucun compétiteur, compte ou invitation supprimé. Log `LOG_EVENT` dédié (édition, utilisateur, statut au moment de la suppression). Si l'édition supprimée était l'édition active d'un admin (cookie), le front retombe sur la règle par défaut.
- **Points de vigilance** : classements ACP / All Time et palmarès recalculés ou dérivés sans l'édition (vérifier s'ils sont stockés ou calculés) ; cache public éventuel.
- **Critères** : tests API (suppression complète en cours et clôturée, archive refusée, profils conservés et rattachables à une nouvelle édition, 403 participant, 404) ; typecheck, `test:run`, `test:release`, test:api concernés (+ test:db si migration de clés étrangères) verts.
