# B-27 — Tour suivant impossible à tirer après des quarts entièrement validés

- **Statut** : Ouvert (2026-11-16) — **mergé** @ `de9890a0` (branche `2a0fd8e7`), déployé sur dev (`33901d34`). Reste à vérifier à l'écran : demies proposées sur l'édition 2027 (session admin du navigateur expirée au moment du contrôle ; le chef de projet ne saisit pas de mot de passe).
- **Cause racine (prouvée par `tests/api/next-round.test.ts`)** : (1) `loadRoundDrawContext` prenait tous les `QUALIFIED` comme vivier ; un perdant de phase finale ne passait `ELIMINATED` qu'à la clôture, d'où 8 joueurs après les quarts → `QUARTER` déjà tiré → `roundKind: null`. (2) aucun tour n'était jamais `COMPLETED` (seul `DRAWN` écrit), alors que le front s'y fie. Avant correctif : `expected 'DRAWN' to be 'COMPLETED'` ; avec le seul statut : aperçu `roundKind: null` ; après : demies (4 vainqueurs) puis finale (2).
- **Correction** : vivier sans les perdants des matchs décidés (`draw.service.ts`) ; tour rendu `COMPLETED` à la lecture quand tous ses matchs sont validés (`edition-assemble.util.ts`, aucune migration). B-26 hors de cause.
- **Vérifié** : gates sur develop après merge (typecheck vert, `test:run` 1523 / 0, `test:release` vert) ; sur la branche `test:bundle` vert, test:api 9 suites 179/179 ; sur dev, `GET /editions/d2ae3cdb…/tours` rend désormais `QUARTER` `COMPLETED` (4/4). Non couvert par un test dédié : enchaînement depuis huitièmes et barrages (même code). Match `RESULT_UNKNOWN` (archives) : compté décidé sans vainqueur, sans effet sur une édition en cours.
- **Constat (utilisateur, dev `07641649`, édition 2027 `d2ae3cdb-7b2a-4d60-a925-c3d2417fd709`, statut `PLAYOFFS`)** : les 4 matchs de quarts sont validés (`GET /editions/{id}/tours` : `QUARTER`, `status: DRAWN`, `matchCount 4`, `validatedMatchCount 4`). L'écran de tirage de tour affiche « Quarts · en cours » et « Le vivier compte 8 joueurs : il ne peut pas être tiré. Vérifiez la qualification. » Impossible de tirer les demi-finales.
- **Pistes relevées par le chef de projet (à prouver, pas des conclusions)** :
  - aucun code serveur n'écrit `ROUND_STATUS.PLAYING` ni `COMPLETED` (seul `DRAWN`, `draw.service.ts`) ; le front (`round-draw.util.ts` : `roundSteps`, `inProgressRound`, `admin-dashboard.util.ts`) s'appuie sur `COMPLETED` ;
  - l'aperçu du serveur calcule un vivier de 8 joueurs (les quart-de-finalistes, pas les 4 vainqueurs ?).
- **Attendu** : une fois tous les matchs d'un tour validés, le tour est terminé, le tour suivant est proposé avec le vivier des vainqueurs (RG13), et l'écran affiche le tour suivant « à tirer ». Corriger aussi les éditions déjà dans cet état (l'édition 2027 de dev doit se débloquer sans manipulation de base à la main, ou via une migration / un recalcul documenté).
- **Critères** : test API reproduisant le cas (quarts validés → aperçu = demies, vivier 4 → tirage → validation → finale) ; même chose depuis des huitièmes et des barrages ; typecheck, `test:run`, `test:release`, suites API concernées vertes ; vérification sur dev sur l'édition 2027.
