# B-30 — Export Excel (.xlsx) d'une édition

- **Statut** : Ouvert (2026-11-18).
- **Demande utilisateur (2026-11-18)** : pouvoir exporter une édition dans un fichier pour Excel.
- **Décisions utilisateur (2026-11-18)** : format **.xlsx, un onglet par partie** ; contenu : **tout ce qui concerne l'édition** ; **admin seulement**.
- **Onglets attendus** : Édition (année, code, nom, date, lieu, description, statut, origine, effectif N, paramètres de qualification, date de clôture) ; Participants (nom, prénom, pseudo, poule, tête de série, tour atteint, points de l'édition RG1-RG2 ; **aucun email ni donnée de compte**) ; Poules (classement par poule : rang, joueur, joués, victoires, défaites, points pour / contre, cap's average) ; Matchs (tour, poule, n°, joueur A, score A, joueur B, score B, vainqueur, statut, départage oui/non) ; Tirages (poules : têtes de série et affectations dans l'ordre ; tours : affiches) ; Phases finales (affiches par tour avec scores, vainqueur de l'édition). Valeurs typées (nombres en nombres, dates en dates), en-têtes en français, colonnes figées et largeur lisible.
- **Contrat proposé** : `GET /api/v1/admin/editions/{id}/export.xlsx` (administrateur) → 200 `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`, `Content-Disposition: attachment; filename="ccc-<code>.xlsx"`, `Cache-Control: no-store` ; 404 ; archives comprises.
- **Bibliothèque** : à choisir côté serveur, uniquement dans le code serveur (jamais dans le bundle navigateur, garde `clientBundleGuard`) ; vérifier `npm ls axios` (axios proscrit, même transitif), `npm audit` (0 high/critical), maintenance active, licence. Préférer une bibliothèque légère dédiée à l'écriture. Justifier le choix dans le ticket.
- **Critères** : test API (onglets présents, en-têtes, une ligne par match / participant, aucun email dans le fichier, 403 participant, 404) en relisant le fichier produit ; édition en cours et archive ; typecheck, `test:run`, `test:release`, `test:bundle`, test:api concernés verts ; Spec API à jour.
