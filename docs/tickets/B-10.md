## Endpoints

Toutes ces routes sont réservées à l'**administrateur**.

| Méthode et chemin | Règles | Refus |
|---|---|---|
| `POST /api/v1/editions` | P1.1 : année, nom, date, description, lieu ; `code` et `chronological_rank` calculés (le `code` d'une deuxième édition la même année reste à définir, en suivant l'exemple `2012a` / `2012b`) | 400 |
| `PATCH /api/v1/editions/{id}` | informations générales uniquement, jamais `status`. **`code` est immuable** une fois l'édition créée (R-9, décision utilisateur 2026-10-20) : c'est l'identifiant des URL publiques (`/editions/2012a`, routage par code confirmé par le front). `code`, `year` et `chronological_rank` sont refusés dans le corps (400, champ hors liste blanche) | 409 si l'édition est `CLOSED` |
| `PATCH /api/v1/competiteurs/{id}` | corriger une identité (`display_name`, nom, prénom, pseudo, avatar) | 404 |
| `POST /api/v1/editions/{id}/participants` | P1.3 à P1.5 : `{ competitorId }` rattache un compétiteur existant ; `{ newCompetitor }` délègue à B-09. **C8 tranché entre leads** : depuis l'écran d'édition, le front appelle cette route, qui crée en une transaction le compétiteur, le compte, l'invitation et la participation. `POST /competiteurs` sert l'écran Référentiel, sans édition. Les deux partagent le même service | **409** si le compétiteur est déjà inscrit (invariant 1) ; **409** si le tirage des poules est validé (Spec API) |
| `DELETE /api/v1/editions/{id}/participants/{participationId}` | retrait autorisé **tant que le tirage des poules n'est pas validé** (Q1, décision utilisateur 2026-10-21) : pendant un brouillon, l'affectation de l'inscrit dans ce brouillon est supprimée dans la même transaction | 409 `REGISTRATION_CLOSED` après validation du tirage |

**Ajout du 2026-10-21 (écart G1 relevé par le front, F-09)** : liste admin des inscrits.

| Méthode et chemin | Règles | Refus |
|---|---|---|
| `GET /api/v1/admin/editions/{id}/participants` | Réponse `IAdminParticipant[]` = `IEditionParticipant` + `editionsPlayed: number` (toutes éditions, comme `ICompetitorListItem`) + `account: { state: ACCOUNT_STATE, invitationExpiresAt: string \| null } \| null`. `account` vaut `null` pour un compétiteur sans compte (archive). `ACCOUNT_STATE` (`../../src/enums/user.enum.ts`, ajout) : `INVITED`, `INVITATION_EXPIRED` (invitation la plus récente expirée et non consommée), `ACTIVE`. **Aucun email ni téléphone.** Le bouton « Renvoyer » du front appelle `POST /competiteurs/{id}/invitation` (B-09) | 401 / 403 hors admin ; 404 édition inconnue |

Transitions d'état : `CREATED` → `REGISTRATION` au premier ajout. Le passage à `POOLS_DRAWN` appartient à B-11.
