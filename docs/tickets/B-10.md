# B-10 — Écritures admin : éditions, identité d'un compétiteur, participants

- **Statut** : À faire, une fois B-08 livré
- **Vague** : 3
- **Worktree** : `../CCC-B-10`, branche `feature/B-10-admin-editions`
- **Dépendances** : B-08 (rôle administrateur). B-09 pour la branche « créer un nouveau compétiteur » de `POST participants` : on réutilise son service, sans dupliquer la création.

## Endpoints

Toutes ces routes sont réservées à l'**administrateur**.

| Méthode et chemin | Règles | Refus |
|---|---|---|
| `POST /api/v1/editions` | P1.1 : année, nom, date, description, lieu ; `code` et `chronological_rank` calculés (le `code` d'une deuxième édition la même année reste à définir, en suivant l'exemple `2012a` / `2012b`) | 400 |
| `PATCH /api/v1/editions/{id}` | informations générales uniquement, jamais `status`. **`code` est immuable** une fois l'édition créée : c'est l'identifiant des URL publiques (`/editions/2012a`, routage par code confirmé par le front le 2026-10-20). `code`, `year` et `chronological_rank` sont refusés dans le corps (400, champ hors liste blanche) | 409 si l'édition est `CLOSED` |
| `PATCH /api/v1/competiteurs/{id}` | corriger une identité (`display_name`, nom, prénom, pseudo, avatar) | 404 |
| `POST /api/v1/editions/{id}/participants` | P1.3 à P1.5 : `{ competitorId }` rattache un compétiteur existant ; `{ newCompetitor }` délègue à B-09. **C8 tranché entre leads** : depuis l'écran d'édition, le front appelle cette route, qui crée en une transaction le compétiteur, le compte, l'invitation et la participation. `POST /competiteurs` sert l'écran Référentiel, sans édition. Les deux partagent le même service | **409** si le compétiteur est déjà inscrit (invariant 1) ; **409** si le tirage des poules est validé (Spec API) |
| `DELETE /api/v1/editions/{id}/participants/{participationId}` | retrait **avant tirage** | 409 si un tirage des poules existe, même en `DRAFT` ; à confirmer en revue |

Transitions d'état : `CREATED` → `REGISTRATION` au premier ajout. Le passage à `POOLS_DRAWN` appartient à B-11.

## Critères d'acceptation

- [ ] Tests d'API : participant renvoie 403, anonyme renvoie 401, sur chacune des 5 routes.
- [ ] Tests d'API : double rattachement renvoie 409 ; ajout après validation du tirage renvoie 409 ; retrait après tirage renvoie 409.
- [ ] Tests d'API : création de deux éditions la même année, avec deux `code` distincts.
- [ ] Tests d'API : `PATCH /editions/{id}` avec `code`, `year` ou `chronological_rank` → 400 ; le `code` en base est inchangé.
- [ ] Les corps sont validés par schéma ; les champs inconnus sont rejetés.
- [ ] Un événement structuré par écriture (`edition.created`, `participant.added`…) porte `userId` et `editionId`, sans donnée personnelle.
- [ ] La doc d'endpoints est à jour.
