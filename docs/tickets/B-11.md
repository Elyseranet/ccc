## Endpoints

A1 : enregistrement d'un tirage **physique**, conformément à RG12 et à `parcours.md` §5, avec un brouillon à chaque affectation.

| Méthode et chemin | Rôle | Statut Spec API |
|---|---|---|
| `GET /api/v1/editions/{id}/tetes-de-serie?poules={n}` | propose les *n* têtes de série (RG9, RG10) et signale les égalités non tranchées | **ajout** à la Spec API |
| `POST /api/v1/editions/{id}/tirages/poules` | crée le tirage `DRAFT` : `{ poolCount, seedCount, seeds: participationId[] }` | existe |
| `PUT /api/v1/tirages/{id}/affectations` | enregistre le brouillon (liste ordonnée `{ participationId, poolRank }`) ; idempotent, puisque le contenu est remplacé | **ajout** à la Spec API |
| `GET /api/v1/admin/editions/{id}/tirages` | brouillons compris, avec auteur et horodatages (C7) | **ajout** à la Spec API |
| `POST /api/v1/tirages/{id}/validation` | fige le tirage, affecte les poules, génère le round-robin (RG15), passe l'édition à `POOLS_DRAWN` | existe |

## Règles de refus

| Cas | Statut | Règle |
|---|---|---|
| `seedCount ≠ poolCount` | 409 | RG9 |
| Têtes de série fournies différentes du top *n* calculé | 409 | RG9. Si `unresolvedTies` existe, l'administrateur choisit parmi les ex æquo ; la règle de choix n'est pas écrite (RG10) : **Je ne sais pas** |
| Deux têtes de série dans la même poule, ou une poule sans tête de série | 409 | RG11 |
| Validation alors que des participants ne sont pas affectés | 409 | — |
| Poules déjà validées | 409 | la Spec API, et la SF : pas d'annulation |
| `poolCount` ≤ 0, ou supérieur au nombre de participants | 400 | — |

La validation se fait en **une transaction**. Elle est idempotente : rejouer la validation d'un tirage déjà `VALIDATED` renvoie 200 avec l'état courant, sans regénérer de match (invariant 6). Les tailles de poules inégales sont acceptées (RG16) ; RG17, la règle de la bière, est une règle de jeu non applicative.

## Amendement de la Spec API proposé (backend-lead, 2026-11-02), à soumettre à l'utilisateur au merge
Le texte est tiré de `docs/api/pool-draw.md` @ ff1df79 et vérifié contre le contrat G7 (`src/interfaces/draw.interface.ts`).

**Règles communes aux 3 routes** :
- rôle ADMIN : 401 `UNAUTHORIZED` sans session, 403 `FORBIDDEN` pour un participant, rôle vérifié avant toute lecture du corps ;
- `Cache-Control: no-store` ;
- erreurs au format `IApiError { statusCode, code, message, details? }` ;
- schémas zod stricts : un champ inconnu donne 400 `VALIDATION_FAILED`.

**1. `GET /api/v1/editions/{id}/tetes-de-serie?poules={n}`** : propose les n têtes de série (RG9) et signale les égalités parfaites (RG10).
- `{id}` = UUID ou code ; `poules` entier de 1 à 20, obligatoire.
- Classement des inscrits :
  1. ACP sur les 5 dernières éditions closes (A8) ;
  2. puis titres, finales, demies, quarts, huitièmes et barrages, en ordre décroissant ;
  3. puis nombre de participations, en ordre croissant.

  Une égalité parfaite n'est jamais tranchée.
- **200** `ISeedProposal { seeds: { participationId, competitor, rank, acp }[], unresolvedTies: participationId[][] }`.
  - `rank` est un rang « compétition » : les ex æquo partagent le même rang.
  - `unresolvedTies` ne contient que les groupes à égalité qui chevauchent la frontière des n têtes de série.
- **Erreurs** :
  - 400 `VALIDATION_FAILED` ;
  - 400 `BAD_REQUEST` (plus de poules que d'inscrits) ;
  - 404 `NOT_FOUND`.

**2. `PUT /api/v1/tirages/{id}/affectations`** : enregistre le tirage physique dans le brouillon. La route est idempotente, le contenu est remplacé, et la liste peut être partielle.
- **Corps** : `{ assignments: { participationId, poolNumber 1..20, drawnOrder 1..200 }[] }`, 200 lignes au plus.
- **Règles** :
  - chaque participation appartient à l'édition du tirage ;
  - pas de doublon de participation ni de `drawnOrder`, les trous étant permis ;
  - `poolNumber` ≤ `poolCount` ;
  - têtes de série fixées à la création ;
  - deux têtes de série ne sont jamais dans la même poule (RG11).
- **200** `IAdminDraw` (`id, kind, roundKind, status, parameters, createdAt, validatedAt, createdBy, validatedBy, assignments`).
- **Erreurs** :
  - 400 `VALIDATION_FAILED` ;
  - 404 `NOT_FOUND` ;
  - 409 `DRAW_INCONSISTENT` ;
  - 409 `DRAW_SEED_WITHDRAWN` (décision utilisateur : on recommence le tirage) ;
  - 409 `DRAW_ALREADY_VALIDATED` ;
  - 409 `REGISTRATION_CLOSED` ou `EDITION_CLOSED`.

**3. `GET /api/v1/admin/editions/{id}/tirages`** : liste tous les tirages de l'édition, brouillons compris, du plus ancien au plus récent, avec l'auteur et les horodatages (C7).
- **200** `IAdminDraw[]`. Ce DTO n'est jamais renvoyé hors de `/api/v1/admin/` et des écritures du tirage. Côté public, `GET /editions/{id}/tirages` ne liste que les tirages validés.
- **Erreurs** : 400 `VALIDATION_FAILED`, 404 `NOT_FOUND`.

**Pour information, sans amendement** :
- `POST /editions/{id}/tirages/poules` remplace un brouillon existant ;
- `POST /tirages/{id}/validation` crée le tour POOLS en `DRAWN` et est idempotent.

**Codes ajoutés**, tous en 409 : `DRAW_ALREADY_VALIDATED`, `DRAW_SEEDS_INVALID`, `DRAW_INCOMPLETE`, `DRAW_INCONSISTENT`, `DRAW_SEED_WITHDRAWN`.
