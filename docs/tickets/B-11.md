# B-11 — Tirage des poules : têtes de série, affectations, validation, génération des matchs

- **Statut** : À faire. A1 tranché le 2026-10-20 : le serveur **enregistre le tirage physique**.
- **Vague** : 4
- **Worktree** : `../CCC-B-11`, branche `feature/B-11-pool-draw`
- **Dépendances** : B-10 et B-03 (`rankSeedCandidates`, `generateRoundRobin`).

## Endpoints

A1 : enregistrement d'un tirage **physique**, conformément à RG12 et à `parcours.md` §5, avec un brouillon à chaque affectation.

| Méthode et chemin | Rôle | Statut Spec API |
|---|---|---|
| `GET /api/v1/editions/{id}/tetes-de-serie?poules={n}` | propose les *n* têtes de série (RG9, RG10) et signale les égalités non tranchées | **ajout** à la Spec API |
| `POST /api/v1/editions/{id}/tirages/poules` | crée le tirage `DRAFT` : `{ poolCount, seedCount, seeds: participationId[] }` | existe |
| `PUT /api/v1/tirages/{id}/affectations` | enregistre le brouillon (liste ordonnée `{ participationId, poolRank }`) ; idempotent, puisque le contenu est remplacé | **ajout** à la Spec API |
| `GET /api/v1/admin/editions/{id}/tirages` | brouillons compris, avec auteur et horodatages (C7) | **ajout** à la Spec API |
| `POST /api/v1/tirages/{id}/validation` | fige le tirage, affecte les poules, génère le round-robin (RG15), passe l'édition à `POOLS_DRAWN` | existe |

## Règles de refus

| Cas | Statut | Règle |
|---|---|---|
| `seedCount ≠ poolCount` | 409 | RG9 |
| Têtes de série fournies différentes du top *n* calculé | 409 | RG9. Si `unresolvedTies` existe, l'administrateur choisit parmi les ex æquo ; la règle de choix n'est pas écrite (RG10) : **Je ne sais pas** |
| Deux têtes de série dans la même poule, ou une poule sans tête de série | 409 | RG11 |
| Validation alors que des participants ne sont pas affectés | 409 | — |
| Poules déjà validées | 409 | la Spec API, et la SF : pas d'annulation |
| `poolCount` ≤ 0, ou supérieur au nombre de participants | 400 | — |

La validation se fait en **une transaction**. Elle est idempotente : rejouer la validation d'un tirage déjà `VALIDATED` renvoie 200 avec l'état courant, sans regénérer de match (invariant 6). Les tailles de poules inégales sont acceptées (RG16) ; RG17, la règle de la bière, est une règle de jeu non applicative.

## Critères d'acceptation

- [ ] Tests unitaires : déjà couverts par B-03 pour le départage et le round-robin.
- [ ] Tests d'API :
  - RG9 renvoie 409 ;
  - une poule sans tête de série renvoie 409 ;
  - la validation crée exactement n(n−1)/2 matchs par poule ;
  - une double validation ne crée aucun match en plus.
- [ ] Tests d'API : un `DRAFT` n'est pas visible publiquement (cf. B-06) ; après validation, il l'est, avec l'horodatage et l'auteur.
- [ ] Tests de concurrence : deux validations simultanées produisent un seul jeu de matchs (verrou `SELECT … FOR UPDATE` sur le tirage).
- [ ] La Spec API (Obsidian) porte les deux routes ajoutées (amendement appliqué par le `project-manager`).
- [ ] Aucun tirage au sort côté serveur : aucune source d'aléa dans le code du tirage (A1, RG12).
