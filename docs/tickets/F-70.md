# F-70 — Pages légales et mails : lire l'identité de l'éditeur dans les variables serveur Coolify

- **Statut** : Ouvert (2026-11-18). Bloquant pour la livraison au client.
- **Constat (2026-11-18, chef de projet)** : CCC ne lit aucune des variables légales partagées de Coolify (règle globale du 2026-11-15 : `LEGAL_STATUS`, `LEGAL_NAME`, `LEGAL_FORM`, `LEGAL_CAPITAL`, `LEGAL_SIREN`, `LEGAL_RCS`, `LEGAL_VAT`, `LEGAL_ADDRESS`, `LEGAL_PHONE`, `LEGAL_EMAIL`, `LEGAL_PUBLICATION_DIRECTOR`, `LEGAL_HOST_NAME`, `LEGAL_HOST_ADDRESS`, `LEGAL_HOST_PHONE`, `LEGAL_HOST_COUNTRY`, `PRIVACY_CONTACT_EMAIL`, `PRIVACY_FORM_RETENTION_DAYS`). Aucune n'est déclarée dans l'application Coolify dev (vérifié par l'API le 2026-11-18). Les pages légales (`src/consts/legal-*.const.ts`, locales) portent des « [À FOURNIR : …] » en dur pour ces informations (dénomination, adresse, SIREN/RCS, capital, forme, téléphone, email de contact, contact RGPD, directeur de la publication, hébergeur).
- **À faire** :
  1. `runtimeConfig.public.legal` (une clé par variable) dans `nuxt.config.ts`, lue par les pages légales via un composable ; jamais de valeur en dur. Valeur vide : « à compléter » hors production ; **bloque la mise en production** (garde du runtime config strict, comme les autres variables requises, et check pre-delivery).
  2. Coolify dev : déclarer `NUXT_PUBLIC_LEGAL_*={{server.LEGAL_*}}` (et `PRIVACY_*`) dans l'application (Coolify ne propage pas seul). Prod : idem au passage en prod.
  3. Remplacer dans les pages légales les « [À FOURNIR] » qui correspondent à ces variables. Les autres « [À FOURNIR] » (textes juridiques à rédiger, durées, fournisseur SMTP, date de mise à jour) **restent hors périmètre** : ce sont des contenus, pas l'identité de l'éditeur ; à lister dans le rapport.
  4. `.env.example` et README : documenter les variables (renvoi à la règle, pas de valeur).
  5. Le mail d'information de promotion admin (B-31) lit `public.legal.email` (même clé) : clé à créer une seule fois, ici ou dans B-31, le second mergé réutilise.
- **Critères** : pages légales affichant les valeurs de dev ; garde de production testée (valeur vide → refus de démarrer en image de production) ; e2e / visuels légaux à jour ; typecheck, `test:run`, `test:release` verts.
