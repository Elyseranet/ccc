## Composants Origam

- **Un seul flux** : chercher → rattacher ou créer → inviter.
- **Recherche** : `origam-select` `autocomplete` `search` `variant="solo"` `rounded="full"` `no-data-text`. Le dernier item du menu est « Créer un nouveau participant » (slot de liste).
- **Avatar (AV-1, contrat B-16)** :
  - Champ `origam-file-field` de la maquette, `max-file-size="2000000"` `show-size`, `accept` limité à JPEG, PNG et WebP. Le contrôle front ne sert qu'au retour immédiat ; c'est le serveur qui fait foi.
  - Erreurs à traduire, une clé i18n par code :
    - 413 `AVATAR_TOO_LARGE` ;
    - 415 `AVATAR_UNSUPPORTED_TYPE` ;
    - 422 `AVATAR_UNREADABLE` ;
    - 400 `VALIDATION_FAILED` ;
    - 401 et 403 ;
    - échec réseau.
  - Affichage : `avatarUrl` (`/api/v1/competiteurs/{id}/avatar?v={empreinte}`, public), ou `null` : on affiche alors les initiales (`origam-avatar` `text`). L'image fait au plus 512 px ; elle est affichée **carrée**, recadrée par CSS (`object-fit: cover`).
  - Création en **deux appels** :
    1. `POST /editions/{id}/participants` avec `newCompetitor`, **sans champ avatar**, qui renvoie le `competitorId` ;
    2. `PUT /api/v1/competiteurs/{competitorId}/avatar`, réservé à l'admin.
  - Si le second appel échoue, le compétiteur existe déjà sans photo. On l'affiche avec une erreur et une action « Réessayer l'envoi de la photo », sans recréer le compétiteur.
  - Endpoint pré-déclaré par F-00 : `COMPETITOR_AVATAR_UPLOAD`.
- **Création** : `origam-form` `validate-on="submit"`, avec nom, prénom, pseudo, avatar (`origam-file-field`, envoyé dans un second appel), email et téléphone, ces deux derniers privés.
- **Email déjà pris** : `origam-text-field` `type="email"` `error` `error-messages`. Refus 409, avec proposition de rattacher le profil existant.
- **Information invitation** : `origam-alert` `status="info"` (lien valable 7 jours ; un renvoi annule l'ancien, A14).
- **Inscrits** : `origam-data-table` `items-per-page="8"` `density="compact"`. États du compte : Invité, Actif, Invitation expirée (→ Renvoyer). Retrait possible seulement avant le tirage.
- **Confirmation** : `origam-snackbar` `status="success"` `location="bottom"`.

## Endpoints

- `GET /competiteurs?q=`
- `GET /editions/{id}/participants`
- `POST /editions/{id}/participants` : rattacher un compétiteur existant, ou en créer un avec `{ newCompetitor }` (sans avatar ; la photo suit par `PUT /competiteurs/{id}/avatar`). Dans ce cas, la route crée en une transaction le compétiteur, son compte, son invitation et son inscription (C8, B-10). `POST /competiteurs` reste réservé à l'écran Référentiel.
- `DELETE /editions/{id}/participants/{id}`
- Erreurs : 409 en cas d'ajout après validation du tirage ; email déjà rattaché à un autre compte ; échec d'envoi de l'invitation.
