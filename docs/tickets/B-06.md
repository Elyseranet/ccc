## Endpoints

Tous sont **publics** et en lecture seule.

| Méthode et chemin | Réponse | Règles |
|---|---|---|
| `GET /api/v1/editions` | `IEditionSummary[]` | ordre `chronological_rank` décroissant, sans pagination (16 éditions, Spec API). Chaque ligne embarque `champion` (nom, pseudo, titres à date) et les compteurs de matchs (C1, C2) : pas d'appel par édition |
| `GET /api/v1/stats` | `IArchiveStats` | **ajout à la Spec API** (C1) : compteurs globaux. Les valeurs dépendent de A16 : avec l'option (a), ce sont 729 matchs dont 554 avec score, pas « 1 414 » |
| `GET /api/v1/editions/{id}` | `IEditionDetail` | vue complète : participants, poules et classements, tours, matchs, tirages **validés**, bracket |
| `GET /api/v1/editions/{id}/participants` | `IParticipationPublic[]` | aucun champ de contact |
| `GET /api/v1/editions/{id}/poules` | `IPool[]`, avec `standing` | RG19 (partiel, A10) |
| `GET /api/v1/editions/{id}/tours` | `IRound[]` | RG13 ; `matchCount` et `validatedMatchCount` par tour (C3 : « 68 / 105 matchs de poule validés ») |
| `GET /api/v1/editions/{id}/matchs?page=&pageSize=&tour=&poule=&statut=&tri=` | `IPaginated<IMatch>` | pagination (Spec API). `statut` est une liste de `MATCH_STATUS` ; `tri=validated_at_desc` donne les derniers scores validés (C3). Côté public, `RECORDED` est **sérialisé en `SCHEDULED`**, pour que rien ne trahisse un score saisi mais non validé (E-f) |
| `GET /api/v1/editions/{id}/tirages` | `IDraw[]` | uniquement les tirages `VALIDATED`, avec leur horodatage ; un brouillon n'est jamais public |

`{id}` accepte l'UUID. L'accepter aussi par `code` (`2012a`), pour des URL lisibles, est une proposition à valider avec le `frontend-lead` (`/editions/<id>` dans `parcours.md`).

## Règles de visibilité (décision E-f, 2026-10-19)

- Une édition en cours est visible. Les matchs non validés y apparaissent avec `status` et `sides[].score = null` : le score saisi (`recorded_score`) n'est **jamais** sérialisé côté public.
- Le classement de poule ne compte que les matchs `VALIDATED`.
- Un match `RESULT_UNKNOWN` (archive) se distingue d'un match « à jouer ».

## Cache

La Spec API parle de deux régimes sur une même route.

- Édition `CLOSED` : `ETag` fort et `Cache-Control: public, max-age=…`, valeur dans `runtimeConfig`.
- Édition en cours : `ETag` calculé sur `max(matches.updated_at, draws.validated_at)` et `Cache-Control: no-cache`. Réponse 304 si l'`If-None-Match` correspond.

## Validation et erreurs

- Paramètres validés par schéma.
- 404 si l'édition est inconnue.
- 400 sur un filtre `tour` hors de `ROUND_KIND`, ou un `poule` non entier.
