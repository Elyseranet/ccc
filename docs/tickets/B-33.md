# B-33 — Promotion d'un joueur en administrateur : confirmation avant d'agir

- **Statut** : Ouvert (2026-11-18).
- **Constat** : `POST /admin/administrateurs {email}` (B-31) promeut directement le compte joueur qui porte cet email. La maquette F-68 validée demande une confirmation « Nommer {nom} administrateur ? » avant l'action, impossible à afficher sans savoir à l'avance qu'il s'agit d'un joueur.
- **Décision utilisateur (2026-11-18)** : ajouter la confirmation au back (un changement de droits se confirme).
- **Comportement** : sans confirmation explicite dans le corps, un email de compte joueur répond 409 `PROMOTION_CONFIRMATION_REQUIRED` avec, dans `details`, le nom affichable de la fiche reliée (ou l'email si pas de fiche) ; rien n'est modifié, aucun mail. Avec la confirmation (`confirmPromotion: true`), comportement B-31 inchangé (promotion, mail d'information ou lien d'activation). Email inconnu ou déjà admin : inchangés. Contrat à documenter dans `docs/api/administrateurs.md`.
- **Critères** : tests d'API (409 sans confirmation, aucune écriture ; 200 avec confirmation ; corps strict) ; typecheck, `test:run`, `test:release` verts.
