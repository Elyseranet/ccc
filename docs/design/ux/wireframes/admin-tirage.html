origam-stepper horizontal (vertical sur mobile). Chaque étape ne se débloque que si la précédente est complète.

1. Paramètres

Le nombre de têtes de série doit être égal au nombre de poules.

SF P2 étape 1 et RG9 : les deux nombres sont paramétrés par l'administrateur et doivent coïncider (sinon refus, API 409). Tailles de poules inégales possibles (RG16) : rappel de la règle de jeu « les joueurs des poules les moins nombreuses boivent une bière » (RG17), purement informatif.

2. Têtes de série

Calculées d'après le classement ACP (RG4, RG9).

Égalité : titres, puis finales, puis demies… jusqu'aux participations, classées du plus petit au plus grand ; au-delà, non tranché (RG10). Le mode de calcul est explicité à l'écran.

5. Validation

La validation fige les affectations. Cette action n'est pas annulable (règle fonctionnelle).

Valider le tirage des poules ?

16 joueurs, 4 poules (exemple). Les affectations seront figées.

Spec : « La validation est définitive ; les sources ne prévoient pas d'annulation de tirage » (SF P2 Échecs). La boîte de dialogue le dit. Reste ouvert (SF Questions ouvertes) : le cas d'un désistement après tirage. La main innocente tire physiquement (RG12) ; qui produit le résultat (serveur ou saisie) : question ouverte de la spec API, ARCHITECTURE.md retient l'enregistrement.
origam-dialog (focus piégé, Échap = annuler, focus initial sur « Annuler »). origam-confirm-wrapper existe mais son rôle (saisie de confirmation) est à vérifier avant usage.

ERREUR D'ENREGISTREMENT

Le tirage n'a pas pu être enregistré. Aucune donnée n'a été perdue : votre saisie est conservée.
